# Как мы определяем намерение

## Почему четыре шага и именно в таком порядке

1. **Нормализация** - приводим текст к одному виду: нижний регистр, без лишней пунктуации. Иначе словари и нечёткий поиск будут промахиваться.

2. **Починка STT** - делаем до подсчёта баллов. STT часто рвёт слова («за писаться») или путает похожие («принести» вместо «перенести»). Проще поправить текст один раз, чем писать отдельные правила под каждую ошибку.

3. **Подсчёт баллов** - смотрим, какие слова и фразы совпали с каждым намерением, и складываем веса. Так видно не только «кто победил», но и насколько мы уверены.

4. **Финальное решение** - отдельный шаг с правилом «лучше переспросить, чем угадать». Даже если что-то совпало слабо, можно вернуть UNCLEAR.

Сначала починка, потом удаление слов-паразитов («ну», «наверное»). Так «за» из «за писаться» успевает склеиться в «записаться», а уже потом лишнее убирается.

## Почему правила и словари, а не нейросеть

| | Правила + нечёткий поиск | ML / LLM |
|---|--------------------------|----------|
| Предсказуемость | Один и тот же текст - один и тот же ответ | Зависит от модели |
| Скорость | Очень быстро на CPU | Нужна сеть или GPU |
| Понятность | Видно, какое слово дало балл | Чёрный ящик |
| Наш случай | 7 типов запросов, ~50 ключевых слов | Избыточно |

В задании просят код без внешних LLM - наш подход этому подходит.

## Как текст сопоставляется с намерением

- **Точное слово или фраза** - полный вес из `intentPatterns.js`
- **Похожее слово** (до 2 опечаток, слово от 4 букв) - 70% веса. Например: «скока» ≈ «сколько»
- **Фраза из 2-3 слов** - дополнительный балл, помогает не перепутать намерения

Все слова и веса лежат в `data/intentPatterns.js`. Новый синоним можно добавить туда, не трогая логику пайплайна.

## Если система не уверена

В коде:

```javascript
if (top.score === 0 || confidence < 0.35) {
  return { intent: Intent.UNCLEAR, confidence, reason: 'low_confidence' };
}
```

**UNCLEAR - нормальный ответ**, не сбой. В реальной системе бот переспрашивает: «Не могли бы повторить, чем помочь?» - вместо того чтобы повести разговор не туда.

Когда возвращаем UNCLEAR:

- **gibberish** - шум, бессмыслица («ыаыы ало»)
- **farewell_without_intent** - только «спасибо, до свидания», без запроса
- **ambiguous_intent** - два намерения почти с одинаковым баллом (BOOK и INFO)
- **multiple_strong_intents** - в одной фразе два явных запроса («хочу записаться и узнать цену»)

## Что можно улучшить потом

**Сейчас не идеально:**

- Словари нужно дополнять вручную
- На очень коротких словах возможны ложные совпадения (мы не ищем по словам короче 4 букв)
- Не учитываем предыдущие реплики в диалоге

**Если проект вырастет:**

- Разные пороги уверенности для разных намерений
- Подбор порогов по реальным логам STT
- LLM только для спорных случаев (гибридный режим)
- Больше типичных ошибок конкретного STT-движка в словаре
